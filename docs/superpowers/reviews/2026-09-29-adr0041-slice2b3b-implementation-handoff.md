**Decisions inside the follow-on 1 repair** (each a question for follow-on 1/2, §7 17-21). (1) **Units and phases.** A unit is SETTLED when it ran to a verdict (a pass or a custody refusal), not when a deadline guard stopped it. Progress is kept per PHASE: the pre-spawn gate is no evidence of what the child leaves (it only says the child may run); the post-exit gate's progress covers a failure known right after the child; the settlement keeps its OWN progress, because it did further I/O after that gate returned. A completion never observes a settled unit again (so a failed child whose post-exit gate completed does not repeat the mount census, a chain, or the root, and a settlement that settled its census does not repeat it). (2) **The pre-spawn row.** The design table marks the tree stages "—" for a pre-spawn refusal; the existing rows (a pre-spawn callback finding the deadline spent beside an entry that appeared) require the tree class to still be observed, so it is, and the mount census and the chains (the child never ran) are NOT. (3) **The census is one unit.** The census of the exact tree stops at its own first fault (it must not descend into unexpected entries); the comparison needs a complete census; the digests and the chain edges do not, and every one of them continues after another fails. (4) **One finding per fault.** The same typed tree fault of the same file seen by two classes (the census's size check and the descriptor's own `fstat` of a resized file) is reported once; findings that name different things (a link seen by the tree and by the chain) are both kept (the existing, tested behavior); the grown-file finding keeps the existing oracle's text (`N bytes were read, and the census measured M`). (5) **Closing-gate text.** The closing gate calls `proof_digests` (its bound parameter is gone with `DigestBoundV1`) and `proof_chains` (it passes a fail-fast `ChainPassV1`): arguments only, the same guards in the same order; `output_chains`, shared with pass B2a, is not called by B2c any more (its B2c-owned copy `final_output_chains` carries the units). (6) **Honest coverage.** K0, the runner's own pre-spawn deadline/command/spawn exits, and K3 (writer, wait, and reader-join errors) have no constructor through the unchanged runner and the existing seams; they share the code path of the constructible rows (`ChildExitV1`, `proof_settle`) and are disclosed rather than claimed by a row. ## 5. Invariants and traps — do not do these

- Never add a Git runner command, a path open, a walker, an object-store route, `unsafe`, a rename/remove/truncate/link, a reservation, release, or charge, a copy of the bootstrap's `HEAD`/`config`/`hooks`, an instant, or a duration to the B2C region — its scan refuses them. `".git"` is named exactly once as the root names; `"HEAD"` and `"config"` are never named; the bootstrap's name is allowed ONLY inside `final_sweep_chains`.
- NEVER read a restored file's bytes through its NAME after a failure is known: the name may be another inode, a link, or a FIFO. The failure-only digest reads ONLY the descriptor the restore retained, at explicit offsets (`read_at`), bounded to the length plus one byte, and its scan forbids a reopened name, a seek, a clone, a retry of an interruption, and the clock.
- NEVER retry an interrupted read in a failure-only observation: it is ONE typed refusal of that file, and the other files are still observed. The injected interruption is a `cfg(test)` seam (`watch_reconcile_reads_for_test`) whose count must stay FINITE so the unrepaired retry ends and a test can never hang.
- A callback's refusal replaces ONLY the route refusal this file made (`FINAL_GATE_REFUSED_V1`). Any other runner error, `BinaryDrift` first among them, is the primary, and the callback's refusal is the first finding beside it; a new text for the synthetic refusal must be changed in ONE place.
- TRAPS hit in follow-on 1: (a) `WantV1` and `DRIFT_V1` already existed in the tests file (the new rows use `ExpectedFailureV1` and the existing `DRIFT_V1`); (b) rustfmt wraps a long signature, so a scan must look for `fn unit(`, never `fn unit(&self`; (c) the counts of a row that start at the post-exit hook INCLUDE the gate's own events, so a settlement row expects two mount censuses (the gate's and the completion's); (d) a child that moves the destination root away (`mv root away; mkdir root`) leaves the root's identity as the only thing that changed, and every moved directory must go to an outside temp directory on the same filesystem; (e) a hook that edits the destination during the settlement models a detached helper truthfully (the existing technique: it runs between the settlement's calls); (f) `--exact` with a mistyped name silently runs FEWER tests: compare the selected count with the list.
- NEVER leave a success-eligible step of a final child out of the deadline. The only `&unpaced` of the final region is the one in `proof_reconcile`, the failure-only helper; `proof_settle` and `proof_child` have none, a new `&unpaced` anywhere is a defect (a scan counts it), and a new success-eligible step needs its own guard after each call, a halting row, and a bracket row.
- The failure-only completion is entered from EXACTLY ONE site, `proof_settle`, once per final child, for every known failure and every settlement failure (timeout or custody finding). It must never call the gate, the runner, or a classifier, never read the clock, and never return a value (its result type is the failure): a scan holds all of that. It never replaces a gate's own finding and never observes a unit an earlier phase settled.
- A new final-child failure exit must say what ran to a verdict since the child exited, in `ChildExitV1`/`SettledV1` (and, for a settlement stage, in `SettlementSeenV1`): the completion observes exactly the rest. A new retained edge is a new unit through `ChainPassV1::unit` (in custody order, the root's identity LAST); a new restored file is a new digest unit; the exit table is `01-failure-exit-enumeration-BEFORE-EDIT.md` in the follow-on 1 evidence directory.
- A runner callback cannot know the child's outcome: both callbacks run the deadline gate. Do not "restore" an unpaced callback gate to keep a timed-out child's chain check; a known failure is reconciled clock-free instead, and (round 4) that reconciliation now includes the mount census and every retained chain for a child that may have run and no completed gate saw.
- TRAPS hit in round 4: (a) `snapshot(root)` calls `std::fs::read` on every non-directory non-link, so a row that plants a FIFO and snapshots BLOCKS FOREVER (RED run 1 hung on it: one thread in `wait_for_partner`); never plant a FIFO or socket in a row that snapshots (use a link, a directory, or a name flood). (b) A directory swapped by `mv` moves the pinned inode's ctime, so the tree class sees it by itself unless the census clocks are stalled; a chain-only row stalls them. (c) `--exact` with a mistyped name silently runs FEWER tests: compare the selected count with the list (RED run 2 ran 13 of 14). (d) A restored metadata file replaced by a link is refused by BOTH the tree class and the chain class, and the helper keeps both. (e) rustfmt splits method chains: a source scan must not anchor on `self.method(` text that a formatter may move to its own line.
- The marker lines `// Pass B1a: …`, `// Pass B1b: …`, `// Pass B2a: …`, `// Pass B2b: …`, and `// Pass B2c: …` must each stay unique in the file: the scans split on them. Keep B2c's marker AFTER B2b's.
- The function names `proof_run`, `proof_closing_gate`, `proof_chains`, `proof_deadline_gate`, `proof_child`, `proof_settle`, `proof_settle_paced`, `proof_retained_digest`, `final_sweep_chains`, and `restore_git_plane_bounded_v1` are looked up by `body_of` (a first-match search of the WHOLE file); the earlier passes' are `gate`, `chains`, `final_gate`, `sweep_chains`, `source_files_unchanged`: that is why the final proof's are prefixed. A new method that repeats an earlier name silently retargets a scan. The unit scan looks up `fn unit(`.
- A guard that the final stage adds or moves changes `FinalShapeV1::expected_staged` (the documented sequence, with each guard's stage), the staging-chain event list, the halting rows (derived from the oracle by stage), and (by index, through `index_in`) the root rows of the chain-swap test. The oracle is the test's own derivation from the filesystem; a halting row's `found` check names the guard it expected.
- The guards are one per filesystem call, in the final stage's own helpers. The earlier passes' `source_files_unchanged` and `sweep_chains` make two or more calls per guard; they are approved and pinned by their own tests, and B2C does not call them. Do not "simplify" B2C back onto them.
- Hooks stand AFTER the call they name. A bracket row is only as sharp as the calls that have a hook (or the mount-census seam): a descriptor's own `fstat` and a directory recheck have none, so a slow return there is held by the exact guard sequence and the halting rows, not by a bracket row.
- A directory's `st_size` and timestamps are facts of the zero-effect tree: any read-only child that writes, locks, or creates a transient entry in a restored directory is refused. Git 2.54.0's `cat-file`, `rev-list`, and `fsck` do not; probe a different Git before claiming the same for it.
- A callback gate that sees a changed identity or length refuses the child BEFORE its result is returned, so such a child's result is not recorded (`final_runs` is one short) and the primary failure is the callback's own error (the typed timeout, for a deadline the callback found spent), with the census or digest failure beside it. A change that moves neither (a same-length in-place write) is seen only by the settle's digest. Rows assert it.
- The test fixture's clock must be the deadline production receives. `run_with_the_actual_deadline` records it; never anchor a crossing at an instant read before phase V and the setup. A new near-expiry row passes a `preparation`.
- The hook table holds ONE hook per hook point (a second silently replaces the first); the halting, slow-return, and bracket rows run on scoped threads, so each row installs its own hooks and its own mount-census seam in its own thread (both are thread-local). A bracket row's window opens at `BeforeFinalChildCensus`, `BeforeFinalChild`, `AfterFinalChild`, and the first census call after the post-exit callback, and closes at the `final-rewind` guard.
- A test frame built with `FrameSpecV1` panics with `OutOfOrder` on a DUPLICATE path (replace an entry with `.without(path).file(path, …)`).
- `list_child_names`'s budget is SHARED across every listing of one census, and the census bound is the number of entries the restore made plus one.
- `/usr/bin/git` (2.39.5) may be on the `PATH` after the lane Git and prints an extra unborn-branch notice; probe with `/opt/git/bin/git` when reproducing a Git diagnostic by hand.
- The route key of a fixture child is a substring of its argv: the reachability child is `rev-list --objects`, not its label `rev-list --missing=print`.
- This container has no `/cache`; the verify cache is `/verify-cache` (read-only; cargo's locking did not refuse). No container runtime CLI exists here, so an image digest cannot be observed from inside.
- Never transfer pass A's, B2a's, or B2b's consuming-flow equivalence to a new caller: B2C proves its own ledger conservation on every outcome.
- A final child's baseline census and digests happen BEFORE the runner is called, and a refusal there returns directly (the child never started, nothing to settle); only a child that ran, or whose callback refused, is settled.
