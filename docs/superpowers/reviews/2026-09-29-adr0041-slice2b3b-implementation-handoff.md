**What this increment is.** B2A is the first create-new Git-plane helper, all in `custody_restore_git.rs` after B1b's region (marker `// Pass B2a: charged second object store`). It takes `&VerifiedGitBootstrapV1` (pass A's proven bootstrap), `&ActiveFramePlanV1` (B1a's complete active prevalidation), the caller's ONE absolute deadline, and the caller's last completed step, and returns `FinalObjectStoreV1` or a boxed `ObjectStoreFailureV1`. It takes no runner, no frame budget, and no second ledger, and it adds no operator surface and no phase-G success type.

- **Preconditions (all before the first write).** `require_prevalidated`: the capsule's active classes include a Captured `RefsAndHead` (Empty is the typed `EmptyRefsAndHead`; nothing is synthesized), the plan names exactly the capsule's active frames in order at the same staged payloads with the recorded length and SHA-256, and pass A's retained `active_frames` equal the classification. `require_proven_bootstrap`: strict fsck proven; the closure's inventory size equals the manifest's; objects, provenance, closure, and the manifest's ObjectDatabase row agree (Captured: reachable closure of the whole inventory, the pack name an object id of the caller's format, exactly the hash-named `.pack`, `.idx`, `.rev` in that order, the pack directory retained; Empty: caller-selected provenance, vacuous closure, an empty inventory). Then the full gate.
- **Creation.** `repository`, `repository/.git`, `objects`, `objects/pack`, `objects/info`, each beneath its retained parent through `create_staging_directory` (entry reserved first, given back only when the create made nothing, device compared with the root's), each pinned and followed by a recheck. For a Captured database, each of the three admitted files: a full gate, the entry reserved, create-new through the pack pin, the device, a recheck, then the stream.
- **The stream.** At most one chunk (64 KiB; a test seam shrinks it) in memory; the clock before every chunk and again after its read (`objects-read`), before the chunk is charged and written; each chunk reserved on the ledger BEFORE it is written; the chunk is written by an explicit loop over `write_step`, so the fact in flight advances with every successful write and a failed or zero-length write stops the copy with a typed `Io` refusal and gives the never-written part of the chunk back to the ledger and the facts (the charge is exactly the bytes on disk); an interrupted read, write, or probe is retried and a short write is continued only after the one deadline is read again (round 3), and once it has passed the accepted prefix stays charged, the rest of the chunk's reservation goes back, and no further call is made; never more than the admitted length (a probe read, itself held to the deadline before its first call and every retry, then proves the source holds no more); the bytes streamed are hashed and compared with the admitted SHA-256; the file is synced, the clock is read again (`objects-sync-directory`), and then its directory is synced; the written file is read back from its own descriptor against the admitted digest; its device, kind, and length are checked; it is retained read-write at offset 0.
- **Rechecks.** Every recheck covers each output directory (still the entry its parent holds), each completed output file (still the regular file its pin lists, same device, inode, length), each admitted source file (still the entry the retained pack pin holds and still the retained descriptor's file), and then pass A's own sweep: staging chains, HOME, XDG, every bootstrap directory, and the destination root's identity LAST. A refusal returns the pins that exist, the whole files, the file in flight with its written byte count, the entries and bytes still charged, whether materialization began, the ledger's figure, and the caller's completed step unchanged. ## 5. Invariants and traps — do not do these

- Never add a Git runner or child, a path open, a walker, an object-store route, `unsafe`, a rename/remove/truncate/link, a copy of the bootstrap's `HEAD`/`config`/`hooks`, or a string literal naming them to the B2a region — its own scan refuses them; the words `walk`, `Command`, `spawn`, `rename`, and `symlink(` in NON-comment code trip it too.
- The marker lines `// Pass B1a: …`, `// Pass B1b: …`, and `// Pass B2a: …` must each stay unique in the file: five scans split on them. Do not copy any of them into another comment, and keep the B2a marker AFTER B1b's region (two inherited scans now end at it).
- Do not put a function name containing `object_store` (or the literals `"repository"` / `.git"`) into the module doc or anywhere before the B1a marker: the pass A scan reads everything there except the test-seam and helper-free sections.
- `Write as _` must stay a LOCAL import in `copy_file`: at module scope it makes `file.by_ref()` ambiguous inside the approved `stream_digest`.
- A refusal never removes anything: a second call over the same destination refuses at `repository` as a collision and gives its own reservation back. Never "clean up" a partial store in this helper or its caller.
- The helper takes `&VerifiedGitBootstrapV1` and never moves or reopens anything: the caller (B2C) keeps the one capsule, ledger, pins, and deadline. Never reset the deadline or pass a fresh budget.
- `charged` in the facts moves with the ledger exactly: `entries * ENTRY_ALLOWANCE_BYTES_V1 + bytes`. Every test run asserts it (`StoreCaseV1::attempt_by`); keep that if a test is added.
- A guard hook belongs BEFORE the clock check it is meant to make slow (`BeforeObjectChunk` precedes `before_deadline`): a hook placed after the check simulates nothing. Trap hit this turn: my first chunk-deadline row put it after, and one more chunk was read.
- A change-in-place hook must act BEFORE the first read of that byte (event 1); at event 2 the byte had already been copied unchanged and the digest still matched. Trap hit this turn.
- Every effect (a create, a charge, a write, a sync) AND every further call on a descriptor must be preceded by a clock read that comes AFTER the last blocking call: a recheck ends in the root's identity (blocking), a read can block, a write can block, an `fsync` can block. Keep `objects-checked` after every non-final recheck and gate, `objects-read` after each read, and `objects-sync-directory` between the file's sync and its directory's. Only the final gate, with nothing fallible after its root identity, omits one. Slowing a guard that does not exist proves nothing, so each guard has a row that slows it at every occurrence and holds that no create, chunk, sync, or final-gate event follows (`b2a_no_effect_follows_a_guard_that_finds_the_deadline_spent`).
- A RETRY or a CONTINUATION of a blocking call is a new call and needs its own clock read (source round 2/2): `before_deadline` after an `Interrupted` read, write, or probe; after a short write's accepted prefix (the accepted bytes stay charged and `give_back_unwritten` returns the rest of the reservation, so the charge stays exactly the bytes on disk); and before the FIRST probe after the last write (the next chunk's guard cannot cover a call inside the chunk, nor the call after the last chunk). A blocking call cannot be preempted: the guard runs when it returns, and being mid-call at the deadline is never permission to start another. Never retry or continue after a refusal, never loop on `Ok(0)`.
- Trap hit this turn: a slow-call hook must be keyed to the path of THE CASE UNDER TEST. A same-length in-place rewrite between the read-back and the end is outside B2a and is B2C's closing digest (master Task 5).
7. **Charging is exact for bytes and conservative for entries.** A chunk is reserved before it is written; a write that fails or writes nothing gives the never-written remainder of that chunk back to the ledger and the facts, so the charge equals the bytes on disk and `written` equals what reached the file (finding 1 of round 1). An ENTRY whose create failed other than by `EEXIST` stays charged (the primitive cannot say whether it was created; a row holds this), and only a create that met `EEXIST` gives its entry back. `active_materialization_began` is set when a directory is created (or a create may have created one); a file always follows five directories, so it is not set again there. A directory created and then refused before its pin existed (a device refusal) is named by its charge, not by a pin.
8. **Test-only fault seams in the production file.** A `#[cfg(test)]` enum (`ObjectFaultV1`, which round 3 gives `ShortWrites`) is read by small wrappers (`create_output_file`, `write_step`, `sync_output_file`, `sync_pack_directory`, and in round 3 `read_chunk_step` and `read_probe_step`) so a full disk, an I/O error, a short write, a refused sync, and a permission refusal can be raised in place of one effect, a thread-local counter (`interrupt_object_calls_for_test`) makes a read, write, or probe return `Interrupted`, and the `ObjectIo` hook runs after each call returns; in a non-test build each wrapper is the plain call. This follows the file's existing hook-and-seam convention. Is it acceptable, or should the wrappers take the effect as a parameter?
9. **Modes.** Files are created `0600` and retained read-write; directories `0700` (the existing primitive's own). Git's conventional `0444` pack modes are not applied; nothing in B2a depends on them.
10. **The module doc paragraph is scanned by pass A's whole-module scan** (it reads everything before the B1a marker, doc included): it names no forbidden word. The scan itself is unchanged and green.
11. **The five statements and the one edge beyond the reviewer's lines.** `enumeration.md` lists every per-call and continuation path; the five defective statements are the main read's `Interrupted` retry, the continuation write after a short write, the `Interrupted` write retry, the probe's `Interrupted` retry, and the first probe after the LAST write (C1). C1 is not a retry: a slow last write was followed by the probe read with no clock read, and the next chunk's guard cannot cover it. I classed it in the same closed class (a call on the same descriptor begins after a blocking call returned, without reading the clock) because the reviewer's own required behavior, "after it returns another call must observe the same original deadline", names it, and because it sits in the third loop. If the cap-3/3 reviewer reads it as outside the class, it is one `before_deadline(deadline)?;` line (R04 removes it and flips PROBE and EVERY).
12. **The guard is `before_deadline`, unlabeled, and there is no retry cap.** A labeled `observe_deadline` per call would add clock labels to every clean run and change the documented guard counts of the inherited `b2a_the_guards_of_a_clean_run_are_the_documented_ones` and `B2A_GUARDS_V1`; the unlabeled guard is the pace the chunk-top guard and `stream_digest` already use, and the labeled guards of a clean run are unchanged. A run of `Ok(1)` short writes or of `Interrupted` is bounded by the deadline, not by a count. Is that the right bound?
13. **A deadline stop gives back the unwritten remainder.** It applies the same `give_back_unwritten(read - offset)` a failed write uses, so the charge stays the bytes on disk, and the accepted prefix stays in the file and in `written`. An interrupted write that follows no prefix gives back the whole reservation. The partial file is kept and refused for reentry as before, never cleaned up.
