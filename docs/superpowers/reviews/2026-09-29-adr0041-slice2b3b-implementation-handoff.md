**What this increment is.** B2B is the metadata step of phase G, all in `custody_restore_git.rs` after B2a's region. `materialize_active_metadata_v1(bootstrap, objects, plan, frame_budget, deadline, completed)` takes `&VerifiedGitBootstrapV1`, `&FinalObjectStoreV1` (B2a's value), `&ActiveFramePlanV1` (B1a's), the caller's frame budget, the ONE absolute deadline, and the caller's last completed step, and returns `FinalMetadataV1` or a boxed `MetadataFailureV1`. It takes no runner and no second ledger and runs no Git child.

- **Preconditions (all before the first write).** The plan is this capsule's complete active prevalidation (an Empty `RefsAndHead` is the typed `EmptyRefsAndHead`; nothing is synthesized), the bootstrap is a proven object store, and the object copy is exactly the copy of this bootstrap's admitted files (completed step, count, names, lengths, digests). Then the full gate (mount census, every retained chain, the root identity last).
- **Each frame.** The clock, a recheck of everything made, the retained descriptor reverified (length and SHA-256, through the approved B1a `reverify_staged_v1` on a duplicate of the retained descriptor, which shares its open file description) IMMEDIATELY before a second COMPLETE decode, then every decoded entry judged by the B1a `ActivePathTableV1` rules again (one table across both frames) BEFORE it is created, the clock again, and the create. The first refusal of what is done with an entry (an admission fault, or a failed create or write) is HELD: nothing after it is judged or created, but the decoder is drained through its trailer, and the decoded bytes are bound to the verified plaintext (count and digest) and the entries to the plan's summary (counts and entry digest) BEFORE the held fault is reported, so a frame that is not whole or not the verified bytes is refused as that; only the deadline and the decoder's own failure end a decode at once.
- **Each entry.** A bounded recheck (the object copy, the chain of directories down to the new entry's parent, every admitted bootstrap file, the staging/HOME/XDG/bootstrap chains, and the root identity last; the full set of metadata entries is NOT rechecked per entry, so the work grows with the entries and not with their square), then create-new beneath the retained parent pin through `create_staging_directory` or `create_output_file`, the entry reserved first (given back only on a collision), the device compared, a recheck, the stream (at most one chunk in memory; the clock before every chunk and after its read; each chunk charged BEFORE it is written; each write an explicit call so the fact in flight advances with every successful write; a short write or an interruption is followed by another call only while the deadline is ahead; a failed or zero-length write gives back the part of the chunk never written), the file's kind/length/device checked, its own entry checked by name through the parent, and a recheck. Directory reuse is only of pins this invocation created; a preexisting name is a collision.
- **Steps.** `Metadata` completes after every frame is whole and the full gate after them passes. The agreement (`Refs`) reads only the retained FINAL descriptors: a full recheck, then each file read ONCE through a reader that hashes and counts exactly the bytes the B1b parsers (`RefsBuilderV1`) consume; a parser fault is held until the unread remainder is drained and the digest and length are compared with the ones the file was written with (integrity first, so a changed file is refused as that ahead of anything it says); then `finish` cross-checks EVERY manifest ref by name and target and every active direct target against the inventory (packed, peeled, loose precedence, HEAD states). ## 5. Invariants and traps — do not do these

- Never add a Git runner or child, a path open, a walker, an object-store route, `unsafe`, a rename/remove/truncate/link, a copy of the bootstrap's `HEAD`/`config`/`hooks`, or a string literal naming a ref, HEAD, logs, hooks, info, shallow, index, module, or worktree path to the B2b region — its scan refuses them; the words `walk`, `Command`, `spawn`, `rename`, and `symlink(` in NON-comment code trip it too. `"config"` appears exactly once (the leaf constant).
- The marker lines `// Pass B1a: …`, `// Pass B1b: …`, `// Pass B2a: …`, and `// Pass B2b: …` must each stay unique in the file: the scans split on them. Do not copy any of them into another comment; keep B2b's marker AFTER B2a's (B2a's scan now ends at it).
- Do not put a function name containing `object_store` (or the literals `"repository"` / `.git"`) into the module doc or anywhere before the B1a marker: pass A's whole-module scan reads everything there except the test-seam and helper-free sections.
- A RETRY or a CONTINUATION of a blocking call on a descriptor is a new call and needs its own clock read (the B2a round-2/3 rule, carried): the B2b write loop reads the deadline after a short write's accepted prefix and after an interrupted write, and once after the last write; a content read from the decoder is NOT retried (any decoder error is `FrameInvalid`, or a timeout when the paced reader expired). Never loop on `Ok(0)`.
- Every effect (a create, a charge, a write) must be preceded by a clock read that comes AFTER the last blocking call: keep `metadata-checked` after every non-final recheck and gate, `metadata-item` after each decoded entry, `metadata-read` after each content read, `metadata-decoded`, `metadata-agreed`, and `metadata-config`. The exact count of each is pinned by `b2b_the_guards_of_a_clean_run_are_the_documented_ones` (`5 + frames + 2·directories + 3·(files + 1)` rechecks); the config-in-place row of `b2b_a_file_that_changes_during_its_own_write_is_refused_with_the_partial_state` acts at the 17th `metadata-checked` of its Empty refs-only run, so re-derive it if a recheck is added or removed.
- A hook placed at `BeforeObjectCreate` runs AFTER the pre-create recheck; to swap something BEFORE it, act at the `metadata-item` guard (or `metadata-config`) instead (`act_at_guard`).
- `FrameSpecV1`/`encode_frame` sort entries into the codec's canonical order and the encoder refuses an entry whose parent is absent or a file; a structure it will not emit needs `raw_frame`/`raw_record` (see `b2b_a_bad_trailer_or_damage_after_provisional_content_keeps_every_partial_byte`). Uppercase top-level names sort before `refs` and `logs`, so the first entry of any frame B1a admits (it requires a HEAD) is a file; but a hand-built frame with no HEAD starts with a directory, and the directory arm's `began` mark is then the only one (mutation D03 flips `b2b_the_second_pass_refuses_what_pass_b1a_refuses_before_creating_it`, which I had predicted it would not: my redundancy argument was wrong).
- The hook table holds ONE hook per hook point: installing a second hook on `DeadlineObserved` (for example a recorder beside an `act_at_guard`) silently replaces the first, the swap never runs, and the run "succeeds". `act_at_guard_recording` does both in one hook; I hit this in the first version of the strengthened swap test.
- A test that reads a restored file must run the step first: the files do not exist before `done`. Use the test's own decode (`expected_frames`) for what they must hold.
- A "changed in place" write must change the byte (writing the byte it already holds proves nothing): the first config-in-place row wrote `[` over the golden config's own `[` and passed for the wrong reason; it writes `X` now.
- Trap hit in the first turn: a global `str.replace` on `planted: 0,\n        },` also matched inherited B2a test rows and added a field to them. I caught it only because I checked that the tests file still starts with the exact base bytes (`git show HEAD:` prefix check, and `git diff --numstat` showing 0 deleted lines) and restored the inherited region byte-exact. Keep that check after every bulk edit of a test file; scope a replace to the region you own.
- Trap hit in the first turn: an edit script that slices a file by a header comment must anchor on the LAST occurrence (or the marker of its own region): the first occurrence was B2a's, and the splice duplicated a large region before I repaired it from the base. Same remedy.
- An early return between opening a decoder or a stream and judging its integrity is a defect class (round-1 WRONG 1 and 2): every `?` there must be the deadline or the decoder's own failure, and every other fault must be HELD until the stream is drained to its trailer or its end and its digest, length, and plan summary are compared; only then is the held fault reported, and nothing after a held fault is judged or created. `ends_the_decode` and `ends_the_parse` are that list; the first one's removal is a disclosed non-flip (a held timeout or decoder failure is re-reported with the same cause by the next clock read or the poisoned decoder), so do not widen it.
- A parse of a retained file must hash the bytes the PARSER consumes, never a separate earlier pass: `LinesV1`'s `BufReader` reads ahead, so the digest sits beneath it (`DigestedReaderV1`) and the unread remainder is drained before the comparison. A separate prehash leaves a window in which the parse sees other bytes.
- The refs-read hook is its own point (`AfterRefsRead`), not `ObjectIo`: `b2b_no_read_or_write_follows_a_call_that_returned_after_the_deadline` slows every `ObjectIo` call on the first file's path, and the refs reads of the same path would join it. A file under test for a parse-time change must span several 8 KiB parser buffers (the reflog of 400 rows does), and the change must land in the part the parsers have not read after the hook's FIRST call.
- Never reopen a staged name: B2b reads each frame through a `try_clone` of the retained descriptor (shared open file description, shared offset). After a failure a staged descriptor can be mid-stream; seek explicitly before any later read.
- Never transfer pass A's or B2a's consuming-flow equivalence to a new caller: B2C must prove its own ledger release on every outcome.
- Mutation drivers must not edit the tests (only the production file), must restore and re-hash the production bytes after EVERY mutation, must run on scratch copies, and must use a filter that cannot select unrelated tests: `git_tests::b2b_`.
- The final gate does not re-hash the restored files: it holds each to its measured device, inode, and length by name through the retained pin, and the agreement already rehashed every frame file from its descriptor. The exact tree/digest check of the whole repository is B2C's closing gate (master Task 5).

Two further statements are unreachable by construction and have no mutation: the defensive symlink fallback arm after the admission (the table refuses a symlink first) and the `read == 0` refusal in the stream (the codec's content reader returns zero only at exhaustion).
- An interruption and a short write are INJECTED through B2a's test-only seams (`interrupt_object_calls_for_test`, `ObjectFaultV1`); Linux regular files do not return `EINTR` or short writes on demand, and the seams model the returns, not the kernel. - A hook that sleeps models a slow call by spending the deadline AFTER the call returned and before its result is examined; what a call does while blocked is not modeled (a blocking call is not preemptible). The slow rows use a 1.2 s deadline and sleep to just past it; both the matrix's controls and the focused run passed in full under the load they ran at, but a machine stalled for over a second before the target call would end a row at an earlier, also typed, timeout and fail its `fired` assertion rather than pass falsely.
- Native macOS and native-ext4 runs, the aggregate gates, and the combined base251..final review are outstanding for whole-2B3b. Linux here is a virtiofs bind mount with an overlay temp directory.

**Questions and choices the reviewer should attack first.**

1. **The bounded per-entry recheck.** Between two entries only the new entry's own chain of metadata directories is rechecked, plus the object copy, the bootstrap files, the staging/HOME/XDG/bootstrap chains, and the root; every metadata directory and file is rechecked in full at each frame's start, after the last frame, before the refs are read, before the config, and at the final gate. A full recheck per entry would be quadratic in the entries (a frame may hold up to the codec's entry budget). Is the bounded reading the master plan's "recheck each newly created chain before writes"? What does a completed sibling swapped mid-frame cost (it is caught at the next full recheck, before any step completes)?
2. **Reading the frames through a duplicate of the retained descriptor.** So the step can borrow `&VerifiedGitBootstrapV1` like B2a (and the approved `reverify_staged_v1` can be reused unchanged), the frame is read through `try_clone` of the staged descriptor, which shares its open file description and offset. It rehashes and decodes through the duplicate and rewinds it explicitly on success; on a failure the shared offset is wherever the decode stopped (B2C must seek). Is that acceptable, or should the step take `&mut` and read the staged value itself?
3. **One hashed stream, and what a hold costs.** The agreement reads each restored file once, through a reader beneath the parsers' buffer that hashes and counts every byte they consume; a parser fault is held until the unread remainder is drained and the digest and length are compared with what was written. A frame's entry fault is likewise held until its decoder reaches the trailer and the decoded bytes are bound to the verified plaintext and the plan. The price is that a refusal reads the rest of a frame or file (reads only, paced by the one deadline, bounded by the caller's frame budget and the refs limits), even after an effect fault such as a full disk. Is that the right price for "integrity outranks content" (B1a's and B1b's rule), and are `ends_the_decode` (the deadline and the decoder's own failure) and `ends_the_parse` (the deadline and a failed read) the complete lists of what may end a decode or a parse at once?
4. **Durability and modes.** No restored file or directory is individually synced, and the frames' modes are not applied (owner-private files, `0700` directories), where B2a syncs each object file and its directory. The master plan's Task 4 does not ask for a sync; is a missing sync a defect here, given the restore record's own durability belongs to 2B3d?
5. **Typed progress.** `Metadata` completes after the gate that follows the last frame (not at the last create); `Refs` after the agreement; `Config` only in a success, which ends in the final gate (so a final-gate failure after the config exists reports `Refs`, with the config in the facts). `active_materialization_began` is THIS invocation's mark (a top-level frame file is always the first create, so a file create marks it, and so does a create failure that is not a collision); the object copy before it already began materialization, so B2C ORs the two. Right?
6. **New error variants and reused B2a machinery.** `MetadataInput` and `MetadataCopy` are new `GitBootstrapErrorV1` variants; the facts reuse B2a's types through aliases; the writes go through B2a's seamed wrappers (`create_output_file`, `write_step`, `give_back_unwritten`), whose names say "object" and whose test seams (`ObjectFaultV1`, the interruption counters, the `ObjectIo` hook) therefore also drive this step. The write loop is a second, deliberately duplicated copy of B2a's guarded loop (reads from a decoder, no probe). Should the loop be shared, at the price of touching approved B2a code?
7. **The one inherited test touched.** B2a's structural scan now ends its region at the B2b marker (5 inserted lines, no assertion changed); the alternative, moving B2b's code into `custody_restore.rs`, would widen about a dozen private items of the approved file. Was the narrower change right?
8. **No pre-write agreement is a parameter.** B2b re-derives the agreement from the final descriptors and does not compare it with B1b's pre-write `RefsAgreementV1` (ordering B1b before B2a is B2C's, master Task 5). Should the step also take that value and require equality?
9. **A frame without a `refs/` directory.** B2b restores exactly what the frame carries and synthesizes nothing, so a captured `RefsAndHead` frame with a HEAD but no `refs` directory yields a `.git` that Git will not accept as a repository (`[MEASURED]` with the lane Git 2.54.0: a bare git directory whose `refs` directory is removed answers `fatal: not a git repository`, and answers normally once an empty `refs` directory exists); B2C's final Git proof would refuse it. I did not make B2b refuse it (the master plan names no such rule). Should B1a/B2b require a `refs` directory?
10. **The redundancy claims.** F05, F08, D03, R06b, HF02, PS02 (§7 above) are argued, not measured (D03 was argued the same way in the first artifact and was wrong). Is any of them actually a live guard?
