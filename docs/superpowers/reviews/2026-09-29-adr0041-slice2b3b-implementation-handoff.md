**Decisions inside the targeted repair** (each a question for the FINAL follow-on 2/2, §7 22-27). (1) **Units are calls.** A unit is a guard and ONE call; it is attempted when the call returned, not when a later guard passes; a unit a guard stopped before its call is not. This replaced the "settled when it ran to a verdict" reading for the census, the digests, and the chains alike (a chain unit is still settled by a verdict, which is now the same thing because each has one call). (2) **The listing bound ends the census.** The one budget (the made entries plus one) is shared by every listing; a listing that exceeds it is a `Bound` finding and ends the census (two added names spend it at the last listing), because no later listing can be bounded and the comparison is then unavailable; an unexpected, replaced, or linked entry never ends it. (3) **An incomplete paced hash is not a fact.** A guard or an I/O error INSIDE the paced read leaves no complete hash; the retained digest then reads from byte 0 (carrying a prefix would mix two moments of the file and could report a clean mix). **Decisions inside the follow-on 1 repair** (each a question for follow-on 1/2, §7 17-21). (1) **Units and phases.** A unit is SETTLED when it ran to a verdict (a pass or a custody refusal), not when a deadline guard stopped it. Progress is kept per PHASE: the pre-spawn gate is no evidence of what the child leaves (it only says the child may run); the post-exit gate's progress covers a failure known right after the child; the settlement keeps its OWN progress, because it did further I/O after that gate returned. A completion never observes a settled unit again (so a failed child whose post-exit gate completed does not repeat the mount census, a chain, or the root, and a settlement that settled its census does not repeat it). (2) **The pre-spawn row.** The design table marks the tree stages "—" for a pre-spawn refusal; the existing rows (a pre-spawn callback finding the deadline spent beside an entry that appeared) require the tree class to still be observed, so it is, and the mount census and the chains (the child never ran) are NOT. (3) **The census is one unit.** The census of the exact tree stops at its own first fault (it must not descend into unexpected entries); the comparison needs a complete census; the digests and the chain edges do not, and every one of them continues after another fails. (4) **One finding per fault.** The same typed tree fault of the same file seen by two classes (the census's size check and the descriptor's own `fstat` of a resized file) is reported once; findings that name different things (a link seen by the tree and by the chain) are both kept (the existing, tested behavior); the grown-file finding keeps the existing oracle's text (`N bytes were read, and the census measured M`). (5) **Closing-gate text.** The closing gate calls `proof_digests` (its bound parameter is gone with `DigestBoundV1`) and `proof_chains` (it passes a fail-fast `ChainPassV1`): arguments only, the same guards in the same order; `output_chains`, shared with pass B2a, is not called by B2c any more (its B2c-owned copy `final_output_chains` carries the units). (6) **Honest coverage.** K0, the runner's own pre-spawn deadline/command/spawn exits, and K3 (writer, wait, and reader-join errors) have no constructor through the unchanged runner and the existing seams; they share the code path of the constructible rows (`ChildExitV1`, `proof_settle`) and are disclosed rather than claimed by a row. The injected `Interrupted` is a `cfg(test)` seam, because a regular file does not produce one on demand.

- NEVER repeat the SIX final-byte gates, or rerun the lossless RED, GREEN, or focused run, merely because this handoff-only successor is committed: the receipts are bound to the e32b7ca6 runtime revision and its unchanged Rust hashes (§6), each gate was expressly a run-once, and only a changed Rust hash re-opens them (a STOP the controller decides) — because a repeated gate is duplicate execution that misreports custody (lossless source 1/2 WRONG 1).

- A CENSUS IDENTITY IS THE EXACT BYTES OF THE OBJECT IT OBSERVES. Never key, compare, look up, deduplicate, or complete a census unit by a rendered name (`lossy`, `render`, `seam`, a `format!`): two raw names whose renderings are equal are two units, and a sentinel string in a set that real names can spell is a collision (the `\u{1}` missing unit). The shared `bootstrap_relative` (two pass-A callers) stays lossy and untouched.

- The remaining display-keyed names are TEST seams only (`observed_dev(seam, …)`, `reconcile_read_call(relative)`): they read a test-supplied display name, are ignored outside `cfg(test)`, and decide nothing in production; do not mistake them for a C decision, and do not 'fix' them without the owner (the design defers the test-only `list_ran`/device SMELL).

(b) `cp -p` keeps the OLD mtime of a restored source, so Cargo can reuse a binary built from other bytes: `touch` the file before a build whose binary you will report. (c) Opening a FIFO blocks forever: the census only `fstatat`s, and a row that adds a FIFO must never snapshot or read it (the existing `snapshot` reads every non-link). (d) The listing bound has ONE entry of slack, so a row that adds N names must remove N expected entries or a `Bound` finding ends the census. (f) A hook path is the RAW path (`canonical_path().join(component)`): compare it as bytes (`Path::ends_with`, `OsStrExt::as_bytes`), never as text.
