1. PRIOR-ROUND ADJUDICATION — Section: prior A2 findings. Status: FIXED — formatter stability, deterministic sizing, the exact `effective()` iterator type, and removal of the unprovable A2a UTF-8 mutation claim are now explicit. FIXED — production delegation and two-commit custody are now specified on their original terms; the findings below identify new constructibility, observability, and repository-contract defects rather than re-reporting those fixed items.

2. BLOCKER — WRONG — Section: Private checked-scan module / production projections. Issue: `CheckedScanOpenRefusalV1` is child-private, but the `pub(super)` scan function returns it and `sweep.rs` must match `CannotEnumerate`. The parent cannot name that variant, and `-D warnings` can reject the less-visible return type. Suggested resolution: make the enum `pub(super)`, or translate refusals entirely inside `checked_scan.rs` into a parent-visible outcome; update the literal seam accordingly.

3. BLOCKER — WRONG — Section: Production projections / injected conformance matrix. Issue: production helpers accept only a root and pin opener, while injected sources and completed results remain confined to `checked_scan.rs`. Consequently, mandatory cases such as injected source-open refusal and iterator-error streams cannot traverse the actual production projections; tests would need disconnected duplicate logic or an unspecified seam. Suggested resolution: freeze production-used result-to-projection interfaces, including source-open refusal handling and a test-only completed-result construction path, then require both filesystem wrappers and injected tests to call them. Disagreement resolution: Rigor is right to classify this as BLOCKER rather than Soundness’s MAJOR because the mandatory injected matrix is not constructible through any declared production interface.

4. BLOCKER — WRONG — Section: Exact projection / non-default observations. Issue: `ExactScanProjectionV1` returns rows but not production-computed `UnusedCandidateDecisionV1` values, tracing capture is forbidden, and probe logs cannot observe early-refusal decisions. An implementation can assign the wrong decision to an `UnreadableCustody` row while retaining identical rows and probe activity, yet the required unchanged-decision test still passes. Suggested resolution: return a private decision-bearing projection row or provide a production-used decision observer, and drive the unchanged event from that same captured decision.

5. BLOCKER — WRONG — Section: Interim A2a handoff. Issue: the instruction not to consult or cite an external template conflicts with repository steering requiring every stable handoff to use `handoff-template.md`; an implementer must violate one contract whichever instruction it follows. Suggested resolution: explicitly designate the complete inline schema as an owner-approved replacement, or reconcile the specification with the required template and include the resulting schema.

6. BLOCKER — WRONG — Section: Gates and completion rule. Issue: the four-command “only completion rule” omits the repository-required pre-commit `cargo run -p a2a-bridge -- validate --repo-hygiene`. Following the specified two-commit protocol therefore permits commits that violate the governing repository contract. Suggested resolution: add and record the hygiene guard at each required pre-commit point, or include an explicit owner waiver.

7. MAJOR — SMELL — Section: Shared selection and mandatory engine. Issue: the central row and completed-result contracts omit literal field names and visibility, the iterator-error count type, construction rules, the exact `into_rows` signature, and the test factory required by the injected matrix. A2a and A2b can consequently choose incompatible seam shapes. Suggested resolution: freeze the complete private definitions and signatures, normally using a `usize` error count, and specify the authorized test construction path.

8. MAJOR — SMELL — Section: Exact outcome / A2b decomposition. Issue: forcing both projections through `into_rows` destroys iterator status and root observations, and `CannotEnumerate` also drops the successfully observed canonical root. A2b immediately needs these values and otherwise must replace the seam or re-canonicalize against potentially changed filesystem state. Suggested resolution: let only the action projection erase metadata; retain iterator status, observations, canonical root, rows, and decisions in a richer private exact outcome while the public A2a wrapper continues returning `()`.

9. MAJOR — WRONG — Section: Gates / two-commit custody. Issue: bare `git diff --check` is vacuous at a clean implementation commit and does not inspect the subsequently added handoff. Committed source whitespace defects or staged handoff defects can therefore escape the claimed check. Suggested resolution: record `git diff --check <base>..<implementation-candidate>` and run `git diff --cached --check` immediately before the handoff-only commit.

10. MAJOR — WRONG — Section: Tracing infrastructure / acceptance criterion 26. Issue: preserving the event literal does not verify exactly one event per retained row or placement after that row’s assessment. Duplicate or prematurely emitted events can satisfy the current evidence. Suggested resolution: without adding tracing capture, require a source audit proving exactly one unguarded exact-absence event call site in the post-`finish` row loop, after decision computation, with no duplicate emitter.

11. MINOR — SMELL — Section: Exact refusal vocabulary. Issue: `ExactScanProjectionRefusalV1` duplicates the existing `ExactAbsenceRootRefusalV1` and is scheduled for immediate translation or removal in A2b. Suggested resolution: reuse the existing vocabulary where sufficient, or define one richer private exact-outcome precursor that can also preserve canonical-root evidence.

12. MINOR — SMELL — Section: Acceptance criteria 4 and 30. Issue: “only the six pinned field-scoped allowances are present” can be read repository-wide, contradicting the four unchanged constructor allowances in `report.rs`. Suggested resolution: scope the six-allowance constraint explicitly to `checked_scan.rs` and state that the four existing `report.rs` allowances remain additional and unchanged.

Verdict: changes required before planning—resolve the five BLOCKER items by making the refusal seam visible, defining production-used injectable projections, exposing production decisions privately, reconciling the handoff-template rule, and adding the mandatory repository-hygiene gate.
