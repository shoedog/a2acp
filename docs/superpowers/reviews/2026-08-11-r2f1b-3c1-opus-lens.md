## Summary

The architecture of this slice is good. The `SpawnAuthorityState` CAS, the pre-ID `RefusedUnknown` fence, the immutable-ID-only removal argv, the composite one-flight teardown, `CanonicalContainerOwnershipV1`, the additive journal events with exact goldens, and the recycled-name control are all well built and well tested at the injected-seam layer. The frozen slots are byte-identical, the real-host V3 closure tests are untouched, and the `dc6b9031` repair is sound.

The problem is the seam where the slice touches the real runtime. `observe_container_identity` is the single new production I/O primitive; **every** production container spawn and **every** production container removal (`:rw` and `:ro`) now routes through it, and it has **zero test coverage** — every unit test in the diff injects a stub `ContainerIdentityProbeFn`. That is exactly why a 3,944-test green workspace does not discriminate here, and it is where all three WRONG findings live.

3 WRONG (one of which disables containerized agents entirely), 10 SMELL.

## WRONG findings

### WRONG-1 — The identity-probe Go template emits a literal `\t`; the parser requires a real TAB. Every production container identity observation fails.

**Location** `crates/bridge-core/src/reaper.rs:703` (template) and `crates/bridge-core/src/reaper.rs:727-729` (split).

```rust
// reaper.rs:700-706
.args([
    "container", "inspect", "--format",
    "{{.Id}}\\t{{json .Config.Labels}}",   // Rust "\\t" → the two bytes 0x5C 0x74
    selector,
])
...
// reaper.rs:727-729
let (immutable_container_id, labels_json) = text.trim()
    .split_once('\t')                      // Rust '\t' → U+0009
    .ok_or(ReapFailure::IdentityUnavailable)?;
```

**Mechanism.** Go's `text/template` copies literal text outside `{{ }}` verbatim; docker's `inspect` path (`cli/command/inspect` → `templates.Parse`) performs no escape substitution — the `\t`→TAB unescape lives in `cli/command/formatter.Context.preFormat()`, which serves `docker ps`/`images`/`volume ls`, not `docker inspect`. So the separator is emitted as backslash+`t`, `split_once('\t')` finds no U+0009, and the function returns `Err(IdentityUnavailable)` for **every** container.

**Primary evidence** (this host, docker 29.4.0, exact argv the code builds):

```
$ docker container inspect --format '{{.Id}}\t{{json .Config.Labels}}' <id> | od -An -tx1 -c
 ... 32 64 66 32   5c  74  7b  22  63 6f 6d 2e 64 6f 63 6b 65 72 2e 63
      2  d  f  2    \   t   {   "   c  o  m  .  d  o  c  k  e  r  .  c
```
Bytes `5c 74` — backslash + `t`. **Control** (same command, real TAB spliced via `printf`): the same offset is byte `09`. The failure is the format string, not the parse, and the fix is one character.

**Constructible input and incorrect observable result.**
1. Any `container_rw` agent under `serve` or `implement`. `AcpContainerSpawn::spawn` (`bin/a2a-bridge/src/main.rs:873`, and `:907` for `spawn_observed`) calls `production_container_identity(&request.runtime, &request.name)` after `AcpBackend::spawn` returns and maps any error to `BridgeError::IdentityUnavailable`. → **every containerized `:rw` prompt fails**, and because `open_inner` then takes the pre-ID path (`crates/bridge-container/src/lib.rs:922-925` → `owner.reap_detached()` → `refuse_pre_id`), the container that `docker run` just created is never removed and the session is permanently fenced (see WRONG-2).
2. `ReapController::production_with_timeout` (`reaper.rs:226-231`) — the `:ro` AcpBackend container reaper, wired at `main.rs:1570` via `ContainerReap::production_controller`. → every `:ro` container reap now fails at the probe and **never issues `rm -f`**.
3. `production_reap_fn` (`reaper.rs:861-872`), wired at `main.rs:780`, is now `if let Ok(observed) = observe_container_identity(..) { remove }` — the `else` branch is silent. → the `:ro` Drop-time backstop reaps nothing.
4. `production_identity_probe` inside `managed_production_v2` (`reaper.rs:184`) — the `:rw` removal gate. Unreachable only because (1) already fails.

Net: **containerized agents do not work and container reaping is fully disabled** in this build. This is not a corner case; it is the default production path.

**Why the gates missed it.** `grep -rn 'observe_container_identity|production_container_identity'` returns exactly six call sites, all production, and **zero tests**. Every `ContainerIdentityProbeFn` in the diff is a stub that returns the expected ID and the canonical label vector (`reaper.rs:1365-1377, 1434-1445, 1537-1549`; `bridge-container/src/lib.rs:499-517, 2517-2528, 2691-2704`), so the tests validate the flight state machine and never the runtime contract.

**Bounded fix.** Replace `"{{.Id}}\\t{{json .Config.Labels}}"` with a real tab — matching the repo's own established convention at `bin/a2a-bridge/src/containers.rs:25` (`LIST_FORMAT`) and `crates/bridge-core/src/sandbox.rs:820` (`managed_inspect_argv`), both of which use Rust `\t` = 0x09. Better still: use `{{.Id}}{{"\t"}}{{json .Config.Labels}}` (the runtime-independent Go idiom), so the code does not depend on which CLI surface unescapes.

**Red regression test.** Extract the parse into a pure `fn parse_container_identity(bytes: &[u8]) -> Result<ContainerRuntimeIdentityV1, ReapFailure>` and pin a golden against the byte string docker actually emits (captured above). Add a docker-gated integration test that spawns a labelled container and asserts `production_container_identity` round-trips the ID and the full `a2a.*` set. Both fail on the pre-fix code.

**Triage.** Real-world trigger: every containerized run. Likelihood: 1.0. Exposure: total loss of the `container_rw`/`:ro` feature plus container leaks. **BLOCKER.**

### WRONG-2 — Putting `inspect` in front of `rm -f` inverts docker's removal idempotency: an already-gone container turns a previously-`Complete` teardown into a permanent, unrecoverable session fence.

**Location** `crates/bridge-core/src/reaper.rs:466-560` (`drive_managed` — probe first, `Err(error) => (Err(error), Err(error))` at `:559`), consumed at `crates/bridge-container/src/lib.rs:364-378` (`ReapOwner::reap_observed`) and `:1327-1335` (`finish_reap`).

**Mechanism.** Verified on this host:

```
$ docker rm -f a2a-review-probe-does-not-exist-9f3c2
Error response from daemon: No such container: ...
EXIT=0                                   # rm -f is exit-0 idempotent

$ docker container inspect --format '{{.Id}}' a2a-review-probe-missing-9f3c2
INSPECT_EXIT=1                           # inspect is not
```

The base's reap was `rm -f <name>` and mapped success→`Ok(())` — so "container already gone" was **`Ok`**, which is exactly what the doc comment at `sandbox.rs:824-825` asserts ("Idempotent at the Docker layer"). The slice now requires a successful `inspect` before removal, so "already gone" is `Err(IdentityUnavailable)`.

`finish_reap` (`lib.rs:1327-1335`) clears `session_reaps` only on `Ok(Complete)`. `reserve_generation` (`lib.rs:848-855`) refuses any new generation while `session_reaps` holds the session. There is **no other clear path anywhere in the crate**. So a non-`Complete` teardown poisons that `SessionId` for the life of the `ContainerRwBackend`, with no CLI, API, or retry that clears it.

**Constructible input and incorrect observable result — trigger A (already-gone container).** Warm `container_rw` agent; the in-container agent exits (crash, watchdog kill, OOM, or normal exit). Containers are composed `run -i --rm` (`sandbox.rs:567`), so docker auto-removes it. `retire()`/`release_session_checked` then probes → `IdentityUnavailable` → `Err` → not cleared. Base behaviour on the identical input: `rm -f` exit 0 → `Ok(())` → cleared → `Complete`. **Regression.**

**Trigger B (transient spawn failure).** Cold `container_rw` agent; one `docker run` fails (image not yet pulled, daemon restart, mount/credential error). `open_inner` → `owner.reap_detached()` → `refuse_pre_id` → the authority is permanently `RefusedUnknown`, so `ReapOwner::reap_observed` (`lib.rs:366-368`) returns `Ok(Unknown)` **forever**. `finish_reap` never clears. Every subsequent prompt for that contextId returns `ConfigInvalid { "session <id> cleanup is still owned by its previous container generation" }` until the bridge process restarts. Base: the detached `rm -f <name>` on a never-created container exited 0 → `Ok(())` → cleared → the next prompt retried the spawn.

The diff itself codifies the regression: the base test `cold_generation_cannot_replace_unacknowledged_cleanup_owner` asserted recovery (`release_session_checked(...).unwrap()`, `spawn.count == 2`); the slice renames it to `cold_generation_cannot_replace_unknown_cleanup_owner` (`lib.rs:3153`) and asserts `spawn.count == 1` with `"Unknown authority must remain a permanent generation fence"`.

**Note on the mandate.** The S2 row ("clear only on Complete, generation-guarded") does sanction retention. What it cannot have intended is a state that is unreachable-from and unrecoverable-by construction: a `RefusedUnknown` authority can never produce `Complete`, so the fence is permanent by design rather than by policy. That needs an operator ruling, but the *regression* against base is not a policy question — the same input used to recover and now does not.

**Bounded fix.** Two independent pieces, either of which closes trigger A:
1. Treat "selector resolves to nothing" as removal-complete, not as identity failure: distinguish `inspect` exit-1/"No such container" from a genuine probe error and settle `Complete` (this restores docker's own idempotency contract and is what the base relied on).
2. Give the fence an exit: allow `clear_reap_owner` when the authority is `RefusedUnknown` **and** the generation is proven never-published (the `SpawnSettlementGuard` already knows this), or expose an explicit `forget_session` reset that clears a non-`Complete` owner after recording the disposition.

**Red regression tests.** (a) probe returns `Err(IdentityUnavailable)` for a gone container → assert `release_session_checked` yields `Complete` and `session_reaps` is empty; (b) spawn fails once → assert the *next* `configure_session` + `prompt` reaches the spawn seam (`spawn.count == 2`). Both fail on the current code.

**Triage.** Trigger A: every warm agent whose container exits before retirement — common. Trigger B: any transient docker failure — common. Exposure: agent becomes permanently unusable for a live contextId; operator remedy is a process restart. **BLOCKER.**

### WRONG-3 — The subordinate ACP cancel is gated behind the container identity probe, and the refusal path also pins the inner backend forever, so the agent is neither cancelled nor dropped.

**Location** `crates/bridge-core/src/reaper.rs:499-559` (`drive_managed` gate arms — `:500-503` `IdentityChanged`, `:504-514` `OwnershipLabelsChanged`, `:559` probe error; all return before `managed.subordinate` at `:520-530` is invoked) and `crates/bridge-core/src/reaper.rs:145-155` (`ManagedReapFlightV1.subordinate` holds the closure for the controller's whole life), constructed at `crates/bridge-container/src/lib.rs:955-961`.

**Mechanism.** The subordinate half is `inner.cancel(&session)` on a **bridge-owned** `Arc<dyn AgentBackend>` minted by this exact generation's spawn. The identity/label gate exists to stop us from `rm`-ing a *stranger's* container — that justification does not extend to our own agent handle. But all four refusal arms skip both halves.

Compounding it: the closure captures `Arc::clone(&inner)` (`lib.rs:956`). That `Arc` lives inside `ManagedReapFlightV1` → `SpawnAuthorityState::Bound(Box<ReapController>)` → `Arc<SpawnAuthority>` → the `ReapOwner` retained in `session_reaps`. `managed` is never taken or cleared after the flight settles. So on any non-`Complete` disposition the inner `AcpBackend` is **never dropped**, and `Drop for AcpBackend` (`crates/bridge-acp/src/acp_backend.rs:7422-7440`) — which is the only remaining termination mechanism, since `ContainerRwBackend` sets `container: None` on the inner's `AcpConfig` (`lib.rs:804`, "`:rw` has its own reaper … the inner AcpBackend's `:ro` reaper stays off") — never runs.

**Constructible input and incorrect observable result.** Production cold `container_rw`, session S, live turn. `docker container inspect` exceeds the 2 s `production_identity_probe` bound (`reaper.rs:184`) under daemon load — the repo's own ops memory documents OrbStack VM memory pressure as a recurring cause. `drive_managed` takes `:559` → `Err(Timeout)`; `remove_container_id` never runs; `managed.subordinate` never runs; `reap_observed` returns `Err` (V2 arm, `lib.rs:376`); `finish_reap` does not clear. The container, its `docker run -i --rm` client, and the ACP agent all keep running until the bridge process exits, and the `ReapState::Done` latch means no later call ever retries. Base on the identical input: `release_cold_checked` called `inner.cancel(session).await` unconditionally, then dropped the only surviving `Arc` at end of scope (SIGKILLing the process group), and attempted `rm -f` with a 10 s bound.

**Bounded fix.** (i) In `drive_managed`, run `managed.subordinate` unconditionally and gate only `remove_container_id` on the identity/label verdict; keep the composite disposition rules unchanged. (ii) Make the subordinate one-shot and releasable — e.g. `subordinate: Arc<StdMutex<Option<ContainerSubordinateCleanupFn>>>` taken by `drive_managed` — so a retained `ReapOwner` fences future generations (S2 intent) without pinning a live agent backend and its process-group backstop.

**Red regression test.** Injected probe returns `Err(Timeout)`; assert `subordinate_calls == 1` and `removal_calls == 0`; then assert `Weak::upgrade` on the inner backend is `None` after the flight settles non-`Complete`. Both assertions fail on the current code.

**Triage.** Trigger: any probe timeout or identity/label drift — and, with WRONG-1 unfixed, *every* teardown. Exposure: leaked container + leaked agent process + unbounded `Arc<dyn AgentBackend>` retention across a long-lived `serve` (one per poisoned session). **BLOCKER.**

## SMELL findings

**S1 — `duration_ms: 0` hardcoded in the container flight settlement.** `reaper.rs:491`. Container reap durations are permanently unobservable in the journal and any downstream projection. Fix: thread the `SystemMonotonicClock` already constructed at `reaper.rs:315`.

**S2 — `drive_managed` can return without settling the flight, and can mis-report a successful removal as retained.** `reaper.rs:471-497`. The pre-dispatch chain (`close_admission`/`journal_intent`/`begin_journaled_dispatch`) returns `FlightRefused` leaving the flight non-terminal; and if `journal_container_removal` fails *after* `remove_container_id` succeeded, the caller sees `FlightRefused` → `Retained`, i.e. "container leaked" for a container that was in fact removed. Direction is protective, so SMELL. Fix: settle `Failed` on the pre-dispatch refusal path; record removal success independently of the journal append outcome.

**S3 — `validate_observed` requires the `a2a.*` namespace to contain *nothing* beyond the canonical set, but `{{json .Config.Labels}}` returns image labels merged with `--label`s.** `crates/bridge-core/src/run_identity.rs:102-118`. Any base image carrying an `a2a.*` label makes every spawn refuse with `IdentityUnavailable` and every reap refuse with `OwnershipLabelsChanged`. Undocumented, untested. Fix: document `a2a.*` as reserved for the bridge, or require the canonical keys to be present-and-equal without forbidding unknown `a2a.*` keys the bridge did not stamp.

**S4 — cold `AgentBackend::cancel` now joins a full composite teardown and propagates its failure.** `lib.rs:1626-1652`. Base returned `Ok(())` after a turn-scoped inner cancel; the new path blocks on up to 2 s `inspect` + 10 s `rm -f` and returns `Err(AgentFailure)` on any reap failure. `tasks/cancel` becomes slow and failable. Defensible under the join-or-refuse mandate, but it is a user-visible semantic change with no note in the handoff.

**S5 — `retire()` now returns `Err` on the first failed generation.** `lib.rs:1798-1846`. All production callers discard it (`main.rs:3099/3516/3540/3548/3557/3566`, `catalog_probe.rs:486`, `smoke.rs:1849`), except `crates/bridge-worktree/src/backend.rs:3402`, which folds it into its own `first_error`. Harmless today because ContainerRw is unwrapped, but it makes a single container-runtime hiccup fail an entire wrapper retirement the moment composition changes. Note in mitigation: all flights are started detached at `lib.rs:1814-1816` before the join loop, so the serial `for` does not serialise the removals.

**S6 — `production_reap_fn` silently no-ops when the probe fails.** `reaper.rs:861-872`. The base always attempted `rm -f`, which docker treats idempotently; the new version skips removal entirely on any probe error. This is the `:ro` Drop-time backstop, i.e. the last line of defence. Fix follows WRONG-2's fix-1.

**S7 — `containers reap` prints `reaped {selector}` even when nothing was removed.** `bin/a2a-bridge/src/main.rs:6964-6990`. The inner loop `continue`s past every runtime whose `inspect` fails, then unconditionally prints success. The operator is told a container was reaped when zero commands ran. Fix: track a per-selector removal count and print `skipped (unresolved)` otherwise.

**S8 — the entire new production I/O surface is untested.** `observe_container_identity`, `production_container_identity`, `production_identity_probe`, `production_remove_attempt`, and the rewritten `production_reap_fn` have zero direct coverage; all six call sites are production. This is the process defect that let WRONG-1 through a green 3,944-test workspace. Fix: extract a pure parse seam and pin a byte-exact golden, plus a docker-gated integration test for the round trip. I would treat this as a condition on the repair, not an optional extra.

**S9 — the single cleanup-disposition field already loses information inside ContainerRw itself.** `lib.rs:372-375` maps every protected-V3 failure except `IdentityUnavailable` to `Retained`, including `SubordinateCleanup` — which by construction (`reaper.rs:549-556`) means the container **was** removed and only the ACP cancel failed. Reporting `Retained` there is factually wrong about the container. Protective direction, V3 not production-armed, so SMELL — but it is direct evidence for the lattice carry-forward below.

**S10 — over-long inspect output degrades to `Timeout` rather than a distinguishable error.** `reaper.rs:715-724`: `.take(N+1).read_to_end(..)` followed by `child.wait()` will block if the child writes past the cap; only the outer `tokio::time::timeout` unwedges it, and the caller then sees `Timeout` instead of "identity output too large". Bounded, so cosmetic.

## Ruling 1 — the lattice BINDING row: **RE-ARGUE ACCEPTED. The two-field split is NOT required in this slice.**

The binding row required, before ContainerRw may produce `Retained`, either an inner/outer two-field cleanup split or a re-argument that carries the container-leak scenario and the opus S2 cell-evicted-accumulator concern. The implementer chose RE-ARGUE (handoff §5). I verified it and it holds — on two independent grounds, the second of which the handoff did not claim.

**Ground 1 — the masking composition is not constructible in production.** The 2c2 RD finding is still true at this tip: `bin/a2a-bridge/src/main.rs:1642` (the `AgentKind::ContainerRw` arm) returns `ContainerRwBackend::new(...)` directly as `Arc<dyn AgentBackend>` with no `WorktreeBackend` wrap; the only `WorktreeBackend::new` call in the binary is at `main.rs:1603`, inside the ACP arm. The warm rebuild path (`main.rs:2799`, `main.rs:2960`) likewise constructs `new_warm` unwrapped. So ContainerRw's disposition reaches checked cleanup unfolded, and nothing can raise it under a `Preserved`.

**Ground 2 — production ContainerRw cannot emit `Retained` at all in this slice.** `ReapOwner::reap_observed` (`lib.rs:370-377`) produces `Retained`/`Unknown` **only** when `protected_v3`; the V2 arm returns `Err(failure)`. Production always supplies `resource_flight_attempt_v3: None` (`main.rs:1158`, the sole production construction of `ContainerRwConfig`), so production ContainerRw is unconditionally V2. The only `Retained` producer in the diff is the injected-factory test `protected_container_exposes_real_generation_and_retains_identity_refusal` (`lib.rs:2653`). The binding row's precondition is therefore not yet met.

**The container-leak scenario, argued for the split.** It is a real hazard, and I want it on the record in its strongest form. Once slice 4 arms `resource_flight_attempt_v3` and any preservation-owning decorator is placed over ContainerRw — the Worktree composition that emits `Preserved` already exists and already composes by lattice max — a ContainerRw cleanup that leaks the outer container reports `Retained`, and the decorator folds it to `Preserved`. `Preserved` is the *intentional* "kept on purpose" state operators read as benign, so a leaked container vanishes from the served projection entirely. That is precisely the failure the row was written against, and S9 shows the single field is already lossy *within* ContainerRw before any composition exists.

**Argued against requiring it now.** (a) The composition does not exist and cannot be constructed by any production factory, verified above. (b) The disposition the split protects is unreachable in production. (c) Reordering the lattice globally would break the already-landed Worktree composition contract — the 2c2 precedent and the BINDING 3c1 row are right that the cheap fix is worse than the disease. (d) The S2 accumulator concern is separately and correctly discharged: `session_reaps` is a backend-lifetime capability, not an evictable cell (`lib.rs:857-860` inserts at reserve; `lib.rs:848-855` refuses a new generation while held; `lib.rs:1327-1335` clears only on `Ok(Complete)` and is generation-guarded), and re-derivation rejoins the identical `Arc<SpawnAuthority>` and controller, so a later checked cleanup gets the stable stored result rather than a fresh `Complete`. I traced that mechanism end to end and it does what §5 claims.

**Condition on acceptance (record this as a binding carry-forward, not a discharge).** The two-field split — or an equivalent non-lossy composite disposition — becomes **required before** the first of: (i) any production constructor supplying `resource_flight_attempt_v3` to `ContainerRwConfig`; (ii) any composition placing ContainerRw inside a preservation-owning decorator. It must land in the same slice as that change, not after it. S9 should be folded into that row as evidence that the single field is already insufficient.

## Ruling 2 — operator disclosure 1: is drop-after-join a correct substitute for `inner.cancel(&session)`?

**Correct and strictly stronger on the success path; unsound on the refusal path — and given WRONG-1 and WRONG-2, the refusal path is currently the only production path.**

**Success path (identity + label gate passes).** The explicit cancel is not lost, it is *relocated*: the subordinate closure built at `lib.rs:955-961` runs inside the composite at `reaper.rs:520-548`, concurrently with `remove_container_id`, under the one flight. This is better than the base: it is exactly-once (`ensure_started` latches at `reaper.rs:588`), linearised against removal, and joined by every teardown entrance rather than racing a stream drop. The existing `retire_cancels_and_reaps` (`lib.rs:3855`) still asserts `inner.canceled` after `retire()`, so the substitution is proven. The *drop* half is also real: `finish_reap` clears `session_reaps` on `Ok(Complete)` (`lib.rs:1836`), dropping the controller and with it the subordinate's `Arc`, so the inner's `Drop for AcpBackend` process-group backstop fires at end of the retire iteration.

**Refusal path.** No cancel happens (WRONG-3: the four gate arms at `reaper.rs:500-514, 559` return before the subordinate; and a pre-ID `RefusedUnknown` short-circuits at `lib.rs:366-368` before any controller exists), **and the drop does not happen either** — `finish_reap` does not clear on non-`Complete`, and `ManagedReapFlightV1.subordinate` pins the inner `Arc` inside the retained `ReapOwner`.

**Direct answer to "can an in-flight turn now outlive retirement in a way it could not before?" — yes.** Base `retire()` called `inner.cancel(&session).await` unconditionally and then dropped the last `Arc` at end of the loop iteration; both were unconditional. The new `retire()` (`lib.rs:1798-1846`) binds `_inner`, drops the dispatch gate, joins, and lets `_inner` fall out of scope — but `_inner` is not the last reference. On any non-`Complete` generation, the turn's agent survives retirement indefinitely with no cancel and no drop. Cancel-token/ACP-latch semantics are therefore *not* preserved on that path.

The bounded fix is WRONG-3's: run the subordinate unconditionally and release it once the flight settles.

## Ruling 3 — operator disclosure 2: the `dc6b9031` test restructure

**Sound. Discriminating power preserved; timeout bounds appropriate. No objection.**

The deadlock diagnosis is correct and I reproduced it by reading: base `retire()` started reaps detached and returned; the new one joins `owner.reap_observed()` at `lib.rs:1834`, while the test's injected attempt blocks on `release.notified()` which is only released after `retire().await` returns. A closed cycle — the old structure deadlocks by construction, not by regression in the production code. Repair choice (a), test-semantics restructure, is the right one.

The restructured test (`lib.rs:4486-4551`) preserves all three invariants:

- **Exactly one attempt call.** `calls == 1` is asserted after the release task is dispatched (`:4532`) and again after both joins (`:4550`). Since `release_task` is created only *after* `entered.notified().await` returns, the entering call is provably retire's, not the release's.
- **Join, not re-dispatch.** The terminal `calls == 1` is the discriminator; `ensure_started`'s `NotStarted` latch makes a second dispatch structurally impossible, and the assertion pins it.
- **No observer retention.** `weak.upgrade().is_none()` after `drop(observer)` (`:4545-4548`), unchanged.

The synchronisation is correct, not lucky. `entered.notify_one()` stores a permit when no waiter is registered, so the main task cannot miss it. `release.notify_waiters()` stores no permit — but on `#[tokio::test]`'s default current-thread runtime the attempt future runs synchronously from `notify_one()` through to `release.notified().await` before the main task can resume, so the waiter is always registered first. And `Notify::notified()` snapshots the `notify_waiters` call count at creation, so the `let notified = …; check(); notified.await;` idiom used throughout `SpawnAuthority::controller` (`lib.rs:281-300`) is likewise race-free.

The 30 s bounds are failure bounds, not success bounds — on the happy path both futures are already resolved when the timeout is entered. A worst case of 60 s on a broken build against a 3-hour workspace wedge is the right trade, and the assertion messages name what regressed.

One incidental strengthening worth noting: `retire_task` is now joined with `.unwrap().unwrap()`, so the test also pins that `retire()` returns `Ok` — coupling it to the new error-propagating `retire()` (S5). That is a gain, not a concern.

## Ruling 4 — operator disclosure 3: S2 `session_reaps` retention

Mechanism verified as described: insert at reserve (`lib.rs:857-860`), new-generation refusal (`lib.rs:848-855`), clear only on `Ok(Complete)` (`lib.rs:1327-1335`), generation-guarded (`lib.rs:1332`). It is a backend-lifetime capability, and it does discharge the opus S2 "cell-evicted accumulator" concern for the lattice ruling above.

Two defects ride on it and are filed separately: the fence has no exit for a `RefusedUnknown` authority (WRONG-2), and the retained owner transitively pins a live `Arc<dyn AgentBackend>` (WRONG-3).
