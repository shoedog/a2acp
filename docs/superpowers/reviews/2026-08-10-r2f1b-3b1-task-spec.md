# R2f1b sub-slice 3b1 — process authority I (Supervised internal to the flight; AcpBackend adapter)

## Description

Slice 2 made *checkout* destruction capability-gated. 3s and 3a landed the
settlement epilogue and the flight core. 3b1 now does the same for *process*
destruction: **no signal without a journaled, admission-closed,
capability-bound flight.** Today signals fire from a raw `Drop` and retirement
paths with no journal and no owner set — every such path must come to join or
refuse.

The flight core you are building on (all in `crates/bridge-core/src/`):
`RetainedResourceFlight` runner (`retained_resource_flight.rs:912` — journal
port `ResourceFlightJournal` `:223` with terminal CAS, `join_blocking` `:1211`
usable from a bare `std::thread`, typed refusal on journal failure, registry
`reserve` `:1591`), `OwnedProcessTreeV1` identity shell (`:1459` — identity
capture + journal hooks, currently NO signal wiring), and the wire types in
`resource_flight.rs` (`ProcessStartIdentityV1` `:91` with
`start_time_ticks`, zero producers today).

### Mandate (all items in scope)

1. **`Supervised` construction becomes internal to `OwnedProcessTreeV1`**
   (`crates/bridge-core/src/process.rs:259`). The flight owns the
   `Supervised`, the process group, the start-identity evidence, and the
   optional `:ro` controller.
2. **All THREE signal paths join-or-refuse:** `impl Drop` at
   `process.rs:530-546` (today a single-stage, unconditional, non-blocking
   `libc::kill(-pgid, SIGKILL)` — the exact forbidden shape), `terminate` at
   `:403-422` (async two-stage SIGTERM→wait→SIGKILL), and
   `terminate_blocking` at `:428-475` — called from
   `crates/bridge-acp/src/acp_backend.rs:2130` inside
   `UnpublishedContainerCleanup::start`, which runs on a **bare `std::thread`
   with no Tokio runtime**: it must join via `join_blocking`/the typed
   refusal path, never an async join.
3. **Flight-before-spawn:** the flight exists and is journal-capable BEFORE
   the process spawns; the returned process binds under the transition lock;
   partial spawn/bind failure records protectively (crash-window tests).
4. **Start-identity probes on BOTH platforms:** darwin
   (`sysctl KERN_PROC_PID` → `p_starttime`) and Linux
   (`/proc/<pid>/stat` field 22). If tick semantics differ across platforms,
   make and DOCUMENT a wire decision (`start_time_ticks` semantics) in your
   design note — do not silently pick one. The Linux lane is
   evidence-or-declared-exclusion (darwin host evidence named either way).
5. **Child-first SIGKILL mechanism:** a descendant registry with per-child
   immutable identity and a deterministic fake-OS ordering test — a bare
   group signal cannot order children. **The containment mechanism must be
   closed against forks concurrent with the containment sweep**: the fake-OS
   ordering tests must include a fork-during-sweep interleaving that the
   mechanism provably terminates and contains (rescan-until-stable,
   stop-then-kill, or equivalent — your design; the red test is the
   constraint). A bare `kill(-pgid)` cannot pass this test; that is the
   point.
6. **Every kill/containment syscall outcome is OBSERVED and journaled** — a
   refused or failed signal is a typed, journaled event, never a discarded
   return code.
7. **AcpBackend adapter:** the flight owns the process resources;
   `cancel`, `escalate_terminate` (`acp_backend.rs:5160`; call sites
   `:4873`, `:6117`, `:6166`, `:6200`), retire, registry retirement, and
   `Drop` all JOIN the flight; ordinary release detaches one owner without
   signaling.
8. **Injectable process-authority port** so the pid gate is deterministic:
   same numeric pid, different immutable start identity → REFUSED, for every
   flight action. Bounded host integration is secondary evidence.
9. **Spawn-caller migration** (census below): no direct `Supervised::spawn*`
   remains outside the flight.
10. **V2 decision + controls:** flights attach universally at the process
    layer (direct sessions must attach an owner if they can share a process),
    but destructive REFUSAL semantics are V3-gated in this slice. V2 teardown
    behavior stays byte-identical, pinned by explicit V2 lifecycle controls
    per changed path — including the `Drop` leak-backstop: a V2 session's
    drop must still reap exactly as today.
11. **Bounded diagnostic rider (no behavior change):** at
    `bin/a2a-bridge/src/compatibility_process_group.rs:599` the resolver
    fail-safe `AnchoredProcessGroup::Drop` currently DISCARDS the
    `libc::kill` return code. Observe and record it (rc + errno, e.g. via
    the existing `signal_attempts` shape and a log line). Do NOT change any
    behavior or touch the resolver tests: this is an always-on discriminating
    probe for a parked pre-existing ~2%/run flake
    (`process_executor_kills_descendants_when_execution_is_cancelled`) that
    is explicitly NOT yours to fix.

### Binding constraints carried from the 3a review record (do not violate)

- **ONE registry per attempt** — wire exactly one flight registry per attempt
  scope; never construct a second registry over the same root.
- **Never build a signal path off `ResourceFlightJournal::records()`** — the
  durable records expose pids as identity evidence for recovery, not as
  signal targets. No code may derive a kill target from them.
- **Join from non-async contexts uses the typed refusal path** landed in 3a
  (`join_blocking` + journal-failure refusal) — a journal failure must refuse
  loudly, never hang a joiner.

### Rules and environment

- The frozen custody transition table gains NO edges. No `AgentBackend`
  trait-surface change (that is 3b2's one consolidated pass) — spawn-caller
  migration only.
- Prefer port-driven deterministic tests (they run everywhere). Any NEW test
  that genuinely requires HOST process-tree/signal semantics (grandchild
  visibility, host PID table) must carry the name suffix
  `_host_signal_semantics` — the hermetic in-container verify excludes that
  suffix and the host gate runs it. Do not chase in-container failures of
  such tests into production surgery; name them and move on.
- Feature-unification gotcha: run feature-sensitive assertions under
  `--workspace` semantics, not only `-p` scoped (serde_json key order etc.).
- Landing estimate ~3,000 LOC including tests. If your landing total
  approaches ~4,500, STOP and report rather than continuing — that bound is
  a tripwire, not a routine crossing.

## Acceptance Criteria

1. `unrelated_process_with_recycled_pid_survives_every_flight_action` green:
   via the injectable port, a same-numeric-pid process with a different
   immutable start identity is REFUSED by every flight action (kill, join,
   escalation, drop-time containment). Red-first.
2. `two_nodes_one_generation_signal_once_and_share_result` green with a REAL
   signal end-to-end through the AcpBackend adapter (row 8: join-if-live —
   the flight signals once; both owners share the result; no PID/name-based
   reconstruction anywhere on the path).
3. `shared_acp_escalation_lists_every_active_owner` green (row 9:
   SIGTERM-ignored escalation lists every active owner).
4. Drop-outside-flight refusal (V3) red-first, AND the V2 drop control: a V2
   session's drop reaps exactly as today (explicit control test per changed
   path).
5. Child-first ordering proven under the fake-OS port, INCLUDING a
   fork-during-sweep interleaving the mechanism terminates and contains —
   deterministic, not probabilistic.
6. Flight-before-spawn crash windows: journal-then-spawn-fails and
   spawn-then-bind-fails both record protectively (tests name the expected
   durable state).
7. A forced-failing kill (via the port) produces a typed, journaled
   refusal/failure event — no discarded rc on any signal path.
8. Start-identity probe: darwin lane green on host; Linux lane green or its
   exclusion declared in the handoff with the darwin evidence named; the
   tick-semantics wire decision documented.
9. `terminate_blocking`'s caller joins from a bare `std::thread` through the
   typed refusal path; regression is watchdog-bounded (fails, never hangs).
10. No direct `Supervised::spawn*` outside the flight: census sites all
    migrated; a repo grep in the handoff shows only the sanctioned seam(s).
11. The diagnostic rider (item 11) lands: kill rc + errno observed at
    `AnchoredProcessGroup::Drop`, zero behavior change, resolver tests
    untouched.
12. Workspace verify green in-container modulo the configured hermetic
    skips; report exact totals in the handoff. Fmt + clippy clean.
