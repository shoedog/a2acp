# T3a increment 3A-2 — typed claim authority

## Description

This is the second half of increment 3A. **3A-1 is merged**: repository-authority
observation now runs behind `ExactAbsenceProbeV1`, `source_common_dir_identity`
delegates to the probe, and no candidate-construction code invokes Git. That half
was deliberately behaviour-preserving — every error message left byte-identical,
320 tests passing, identical to its base.

**3A-2 does the retyping, and it carries all of 3A's behavioural red.**

Two changes, both in `crates/bridge-worktree/src/sweep.rs`:

1. **Map every string-valued `from_claim` / `from_bound` failure** to its typed
   `ClaimAuthorityObjectV1` / `ClaimAuthorityUnavailableReasonV1` pair, per the
   mapping table below.
2. **Remove the admitted-record `.ok()` discard.** Today the tail reads
   `from_claim(..).ok()` then `.unwrap_or(Refused)`, reporting
   `Assessed(Refused)` — an assessment for something that was never assessed.
   Construction failures must report
   `CannotConstructSubject(ClaimAuthorityUnavailable(..))`; **post-construction
   observation failures still report `Assessed(Refused)`**, and that distinction
   is the point of the slice.
