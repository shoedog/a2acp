# T3b dispatch plan and T3b-1 task spec

## Slice Plan

Base: `cafeae13`. T3a reports historical eligibility; T3b must establish action-time authority and is the first part of this lane permitted to change custody state or unlink a custody marker.

### Hard rules

1. **A report is never authority.** A T3b actor may use `ExactAbsenceSweepReportV1` and an entry’s exact `enumerated_name()` only as locators. Under its own refusing lock window it must re-open the configured root, re-read the exact named record descriptor-relatively, reapply current placement and population admission, rebind source/root/worktree/common-directory identities and repository authority, repeat target and Git-registration observation, and refuse if any observation changed or cannot be proved. The action-time authority and locks must remain alive through every eventual transition and unlink.
2. **The stale-report tripwire is mandatory.** `stale_report_cannot_authorize_action_without_reproof` must create an historically authorized report, change the target or registration before T3b acquires its locks, and prove that T3b returns a refusal without transitioning or unlinking. This test fails any implementation that treats `effective()` or its assessment as a warrant.
3. **Fail closed.** A present target, a present registration with an absent target, any `CannotProve`, any observation error, any identity change, and any contended or unavailable lock all refuse. Only independently current target absence plus current registration absence may mint action authority.
4. **No production unlink before the final slice.** The proof seam, refusing lock window, readiness decision, same-object marker binding, and transition mechanism must be accepted and merged before the production unlink edge is connected.
5. **Lock order and policy remain fixed.** T3b acquires publication cell then custody cell, both with refusing acquisition. It does not activate or test a new blocking-acquisition policy. A transition writer arriving second may continue to use the existing blocking side of the established asymmetry.
6. **The transition table remains frozen.** `ProtectionPrepared -> UnusedSettled` is the only settlement transition. `PreservationUnknown { reason: MaterializationInFlight }` receives the same state-agnostic marker-removal authority but no transition-table edge.
7. **The target and provider are never removed by T3b.** The only unlink is the exact custody-record marker proven current under the pinned parent.
8. **Falsification license.** The repository at the accepted slice head is authoritative. If an implementer finds any anchor in this plan false, they must stop and report the exact symbol and contradictory code. They must not adapt the task silently.

### Verified baseline

- `WorktreeCustodyStateV1::UnusedSettled {}` exists, forbids a claim, and has no production producer. Its sole incoming table edge is `ProtectionPrepared -> UnusedSettled`; the frozen table has ten edges.
- `remove_worktree_if_safe` is legacy checkout removal. Its sibling-name guard and under-root guard run before lock acquisition or target access. T3b must preserve that ordering but must not reuse its raw path-addressed removal as B20 marker unlink.
- `host_git` has a private async `registration_absent` and a separate private synchronous `registration_absent_sync`. T3a’s synchronous reporting probe uses the latter. T3b needs an async trait seam backed by the former.
- For a complete scan of a pinned healthy root, `has_authoritative_scan()` is already true. Production `effective()` nevertheless yields nothing because `EXACT_ABSENCE_POLICY_READY_V1` is false.
- `effective()` has no production consumer at `cafeae13`; all current calls are tests.
- The dropped-configure phase battery and `nonreturning_custody_sync_transfers_pre_effect_owner` already exist. T3b carries them as regression gates and does not reimplement preparation-flight ownership.
- An `UnusedSettled` record contains neither the prior claim nor source/common-directory binding. Therefore a crash after the durable transition but before unlink leaves a safe marker, not a fresh warrant. T3b must not retry that marker from its state or a report alone. Without independently reconstructible current source authority, it remains as safe residue.

### Slice details

#### T3b-1 — Action-time reproof authority

Own the async/trait seam and an effect-free authority object that retains the current root and marker descriptors plus the refusing publication and custody guards. A preliminary record read may derive the lock keys, but it is locator evidence only. After both locks are held, re-open and re-read the exact enumerated child, compare it with the preliminary object, reapply current policy, and perform the async exact-absence observation with before/after identity brackets. This slice’s full task spec follows below.

#### T3b-2 — Readiness and observation-only boot consumer

This is the only slice that flips `EXACT_ABSENCE_POLICY_READY_V1`, and the flip is the slice’s reviewed decision rather than incidental wiring. Its red control must show that the boot consumer receives zero effective candidates with readiness false and the exact admitted population with readiness true. The flip is permitted only with accepted T3b-1 evidence: stale-report refusal, tri-state refusal, both contention orders, full workspace gates, and review confirmation that no report decision reaches an effect.

This slice makes `effective()` a production consumer for the first time. It remains a historical hint filter: the boot consumer invokes T3b-1 reproof and drops the resulting authority after reporting the current decision. It performs no custody write or unlink.

#### T3b-3 — Same-object marker authority

Bind the current regular marker through the retained root descriptor, no-follow, and retain the opened marker object. Immediately before any future unlink, the name must still identify that same object. A symlink, non-regular entry, multiply linked file, missing name, replacement, changed root, or failed identity comparison refuses.

The authority is state-agnostic after current admission and exact absence, so it serves both `ProtectionPrepared` and `PreservationUnknown { reason: MaterializationInFlight }`. No provider operation, raw path unlink, transition, or production removal is introduced.

#### T3b-4 — Transition mechanism

Add the recovery-side `UnusedSettled` producer as a production-inactive mechanism. It accepts only the live T3b marker authority over a currently reread `ProtectionPrepared` record, publishes the already-legal `UnusedSettled` replacement descriptor-relatively, syncs the parent, reopens the replacement, and returns authority over that replacement while retaining the same refusing locks.

For `PreservationUnknown { reason: MaterializationInFlight }`, return the existing marker authority unchanged; add no transition edge. A transition error or ambiguous parent sync never reaches unlink authority. Tests must pin the ten-edge table and prove that a transition cannot be called with a report entry, raw path, stale authority, or wrong current state.

#### T3b-5 — Transition-then-unlink activation

Connect the boot consumer to the accepted mechanisms. For a currently admitted `ProtectionPrepared` record, hold one refusing window across current proof, durable transition to `UnusedSettled`, reopening and binding the replacement marker, descriptor-relative unlink, and parent sync. For the 2b2 `PreservationUnknown { reason: MaterializationInFlight }` population, use the same current exact-absence proof and marker authority but perform no transition.

The unlink must address the retained parent descriptor and validated single-component name, verify immediately before the syscall that the name is the opened same regular object, never follow a symlink, and sync the parent after success. It never calls `WorktreeProvider::remove`, `remove_worktree_if_safe`, `remove_dir_all`, or a raw path `remove_file`.

Crash ordering is explicit:

- Before transition: the original candidate marker remains.
- After durable transition and before unlink: `UnusedSettled` remains as safe residue. Its empty state and absent claim do not authorize a later retry.
- After unlink but before confirmed parent sync: report a typed ambiguous outcome, never success.
- After confirmed parent sync: report marker settlement complete.

The final red-first battery includes:

- `unused_candidate_settles_only_after_exact_absence`: target present refuses; target absent but registration present refuses; any cannot-prove refuses; both absent affects the marker only.
- Both actor/writer contention orders at the complete proof→transition→unlink boundary.
- Marker replacement and symlink negatives immediately before unlink.
- Crash injection before transition, after transition, after unlink, and at parent sync.
- A frozen-table control proving no `PreservationUnknown -> UnusedSettled` edge.
- The existing dropped-configure tests for every phase and `nonreturning_custody_sync_transfers_pre_effect_owner`.

## Description

Implement **T3b-1 only** on base `cafeae13`: the effect-free action-time exact-absence authority described above. The delivered slice cap is 770 added nonblank repository lines, including tests.

Add a dedicated `sweep::action` surface with:

- An async `ActionTimeExactAbsenceProbeV1` trait. `HostGitWorktree` implements it using the existing private async registration probe. Keep T3a’s synchronous `ExactAbsenceProbeV1` unchanged.
- A non-cloneable, non-constructible-outside-the-module, `#[must_use]` `ActionTimeExactAbsenceAuthorityV1`.
- A typed `ActionTimeExactAbsenceDecisionV1::{Proven, Refused}` and typed refusal categories covering root/record/policy changes, placement or claim-authority failure, lock contention/unavailability, target presence, registration presence, and unprovable observation.
- An async entry point that accepts the current configured root and exact enumerated child name. It must not accept a report decision, assessment, record path, raw authorization boolean, or previously constructed candidate as authority.
- A refusing dual-lock wrapper that acquires publication cell then custody cell using existing nonblocking acquirers and retains both guards in reverse release order.

The ordered protocol is mandatory:

1. Open and pin the current configured root independently of the report.
2. Read the exact enumerated child descriptor-relatively and no-follow only to derive the proposed target and custody lock keys.
3. Apply the sibling-name and under-root guards before target access or lock-directory creation.
4. Acquire publication cell then custody cell, both refusing.
5. While holding both, re-open/revalidate the root and re-read the exact named record. Refuse if the root, record object, canonical bytes, target path, custody id, or policy-relevant content changed.
6. Reapply the current construction guards and population admission from the current record. Reuse/refactor the existing policy implementation; do not create a second table.
7. Reconstruct source/root/worktree/common-directory and source/common-directory authority from the current record and current root.
8. Run the async current exact-absence probe. Bracket its awaited Git observation with current identity and target observations.
9. Mint authority only for current target absence plus current registration absence. Retain the pinned root, exact record name and object, current decoded record/candidate, and both lock guards in the authority.
10. Drop releases authority without any transition, unlink, provider operation, or other mutation.

Do not modify `EXACT_ABSENCE_POLICY_READY_V1`, `LEGAL_CUSTODY_TRANSITIONS_V1`, `bin/a2a-bridge`, backend materialization, preparation-flight code, or any production sweep caller in this slice.

The repository is authoritative. If any named type, privacy boundary, lock order, state rule, or probe behavior differs at the actual base, stop and report the contradiction instead of changing the boundary.

## Acceptance Criteria

- Write the following red tests before implementation, with bounded channels/timeouts for concurrency:

  - `stale_report_cannot_authorize_action_without_reproof`
  - `action_time_exact_absence_refuses_present_registered_and_unprovable`
  - `action_time_authority_requires_current_both_absent`
  - `action_time_redecision_refuses_a_changed_root_or_record`
  - `action_time_forgery_guards_precede_lock_touch`
  - `writer_first_refuses_action_time_recovery`
  - `action_time_recovery_first_holds_both_cells_until_drop`

- The stale-report test first obtains a report whose row was historically authorized, then changes the target or Git registration before action-lock acquisition. It proves refusal, unchanged marker bytes/state, and no effect. An unchanged matched control mints authority.
- The tri-state test proves that target present, registered-but-target-absent, and every unprovable/error result refuse; only both-currently-absent mints authority.
- A pre-lock read cannot become authoritative. The post-lock record read, current admission, identity binding, and exact-absence probe are all observed in the tests.
- Both locks use refusing acquisition in publication→custody order. Writer-first refuses immediately. Actor-first proves both cells remain held until the authority is dropped, after which the writer proceeds.
- The two placement/forgery guards run before any named-target access or lock-directory creation.
- A changed, symlinked, non-regular, multiply linked, unreadable, or missing record refuses without mutation.
- The authority type cannot be cloned or constructed from a report, raw path, boolean, decision enum, or stale candidate.
- `HostGitWorktree` uses the private async registration path for the new trait and retains before/after identity and target brackets. `CannotProve` never maps to absence.
- `EXACT_ABSENCE_POLICY_READY_V1` remains false, `effective()` gains no production consumer, `UnusedSettled` gains no producer, and the transition table remains byte-for-byte unchanged.
- The existing dropped-configure phase tests and `nonreturning_custody_sync_transfers_pre_effect_owner` remain green.
- Run and report totals for:

  - `cargo fmt --all -- --check`
  - `CARGO_INCREMENTAL=0 cargo test -p bridge-worktree --locked`
  - `CARGO_INCREMENTAL=0 cargo clippy --workspace --all-targets --locked -- -D warnings`
  - `CARGO_INCREMENTAL=0 cargo test --workspace --locked --no-fail-fast`

- If the environment cannot run the full workspace gate, run the largest repository-defined hermetic subset and report every exact exclusion and reason. Do not rebaseline or silently skip a failure.
- Report the added-nonblank total. Stop at 770 and report remaining closed work rather than exceeding the cap.
