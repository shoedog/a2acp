# T3a increment 3A-1 — move Git authority observation behind the probe

## Description

Increment 3 was split into 3A and 3B before implementation. **3A has now been
split again**, because its first dispatch stopped correctly at its own cap gate:
the agent measured 509 nonblank added Rust lines against a 500 hard cap **before
formatting and before finishing**, refused to stage an invalid candidate, and
reported. That stop was right, and 509 is a floor, not a total.

This is **3A-1**, the first of the two halves.

### Why this half comes first

3A bundled two changes that look separable but are ordered:

1. **the port** — `ExactAbsenceCandidateV1`'s claim construction shells directly
   to Git today. `source_common_dir_identity` in
   `crates/bridge-worktree/src/sweep.rs` runs
   `git -C <source> rev-parse --path-format=absolute --git-common-dir` inline.
   The design requires all Git authority observation to move behind
   `ExactAbsenceProbeV1`.
2. **the retyping** — every string-valued `from_claim` / `from_bound` failure
   becomes a typed `ClaimAuthorityObjectV1` / `ClaimAuthorityUnavailableReasonV1`
   pair, and the admitted-record `.ok()` discard is removed.

Four of the messages the retyping must map — the `source authority probe …`
family — live **inside the function the port relocates**. Retyping first would
type them in a location that then moves, which is churn and makes both halves
harder to review.

**So 3A-1 does the port and nothing else. 3A-2 does the retyping, rebinding to
your accepted head.**

### What 3A-1 must do

Move repository-authority observation behind `ExactAbsenceProbeV1`:

- add a repository-authority observation method to the trait;
- supply it in **all four** current implementations — `HostGitWorktree` in
  `host_git.rs`, and the three test probes (`Probe` in `checked_scan.rs`,
  `BothAbsentProbe` and `RecordingProbe` in `sweep.rs`). Verify that count
  yourself; the trait is qualified as `super::ExactAbsenceProbeV1` in two of them,
  so a naive grep finds only two;
- route `source_common_dir_identity`'s Git invocation through it, so no
  candidate-construction code in `sweep.rs` shells to Git.

### This half is behaviour-preserving

**Keep every error message byte-identical.** The retyping is 3A-2's. A caller
must not be able to tell from behaviour that the port happened — same decisions,
same messages, same probe-call counts for existing scenarios.

That means 3A-1 has **no genuine behavioural red**. Its evidence is
characterization and structural: that Git is no longer invoked from
candidate-construction code, that all four implementations supply the method, and
that existing decisions and messages are unchanged. Classify it that way and do
not manufacture red.

If a test can distinguish before from after by anything other than *where* the
Git call originates, that is a behaviour change: stop and report.

### Scope fences

3A-1 does **not**:

- change any error message, or add/remove any arm of
  `ClaimAuthorityObjectV1`, `ClaimAuthorityUnavailableReasonV1`,
  `IneligiblePopulationV1`, or `CannotConstructSubjectV1`;
- remove the admitted-record `.ok()` discard, or change what a construction
  failure reports — both are 3A-2's;
- retain or bracket the custody-root identity, or add the degraded matrix — 3B's;
- change population admission or placement-guard precedence from increment 2;
- set `EXACT_ABSENCE_POLICY_READY_V1` to `true`, or change `effective()` or
  `entry_is_effectively_authorized_for_policy`;
- add ownership, locking, transition, unlink, or removal authority. **T3a decides
  and reports; T3b acts.**

### Sizing

Derived from sol's own measured rows for this work — the repository-authority
port and four probe implementations projected at 80, plus its share of assertion
migrations and byte controls — with headroom, because this lane has now missed
three consecutive caps in the same direction and the correction belongs in the
cap rather than in the evidence.

Count added nonblank physical lines in changed `.rs` files after formatting.
**Measure before editing and again before committing.** If the estimate will
exceed the cap, stop and report a revised split rather than compressing evidence

### Operator-owned gates

The implement container's egress cannot fetch the pinned `a2a-lf` dependency, so
`cargo` cannot build there. You make the implementation-candidate commit only;
the host operator runs the gates and makes the handoff-only evidence commit. Do
not attempt the gates, do not run `git diff --cached --check`, and do not
fabricate totals.

**Stage your work.** The bridge commits what you stage and silently discards what
you do not. The previous dispatch correctly left everything unstaged because it
was stopping at a cap; if you are producing a candidate, `git add` the files that
belong in it.
